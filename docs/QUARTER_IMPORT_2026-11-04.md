# 이전 쿼터 기록에서 선수·위치 선택 가져오기

상태: **2026-11-04 15:17 UTC 운영 배포 READY·대표 alias 확인**. 공개 UI 직접 검증과 실제 DB 저장은 아래 한계에 따라 미실행이다.

## 새로 가능한 일과 선택 근거

감독·기록자가 이전 쿼터에 기록된 선수 중 원하는 선수를 직접 선택하고 그 위치를 빈 쿼터의 초안으로 재사용한다. 기본 선택은 0명이며 최종 라인업을 추론하지 않는다. 기존 선수 통계·차트의 중복 추가가 아니다. 재사용 기회가 생긴다는 가설이며 수요·시간 절약·성장 효과는 확인되지 않았다.

[실제 다섯 역할 협의](AGENT_DISCUSSIONS.md#2026-11-04-신규-가치-기능-협의)에서 조건부 선택했다. [SubTime 개발자 설명](https://play.google.com/store/apps/details?hl=en&id=com.gametimes)의 라인업 저장과 [TeamSnap 공식 안내](https://helpme.teamsnap.com/article/231-create-a-game-day-roster-lineup)의 참석 명단을 활용한 직접 구성은 기능 패턴 참고다. 경쟁 제품의 효능·수요·유료 기능이 Soccer Note에서 입증됐다는 뜻이 아니다.

작업 등급은 S2의 기존 인증 화면 기능이다. 공개 검색 경로·네이티브 SDK/권한 변경이 없어 discoverability와 store compliance는 이번 변경에서 적용 제외한다. 현재 Capacitor가 원격 웹을 표시하므로 모바일 웹 상태·접근성은 검증하고, 실기기/스토어 완료로 확대하지 않는다. 기존 데이터 접근 경계는 독립 코드 리뷰에서 확인한다.

## 구현 계약

- 같은 경기의 직전 쿼터 기록을 사용한다. 대상 저장 기록과 현재 초안이 비어 있을 때만 진입하며 적용 직전에 다시 검사한다.
- 선수 ID·포지션·유효 좌표만 로컬 초안으로 만든다. 골/도움/평점/클린시트/기여도/텍스트/미디어/교체 기록/원본 행 ID는 복사하지 않는다.
- 선수 선택은 0명부터 시작한다. 중복 선수 기록·상충 정보·현재 명단 부재·잘못된 좌표는 이유와 함께 차단한다. 선택한 서로 다른 선수의 동일 좌표 충돌은 임의 재배치로 해결하지 않는다.
- 원본 교체 데이터의 OUT/IN만 표시하며 선발·최종 출전·출전 시간을 추정하지 않는다. 모든 기록을 자동으로 최종 라인업으로 변환하지 않는다.
- DB의 0–100 좌표 중 기존 편집 영역 x=8–92/y=10–90 밖은 별도 사유로 선택 불가 처리한다. 경계에서 잘리는 선수 버튼을 피하려는 보수적 범위이며 원본 좌표를 잘못된 데이터로 단정하거나 조용히 보정하지 않는다.
- 기존 피치가 미리보기다. 사용자가 검토·수정하거나 기존 미저장 나가기 흐름으로 취소한다. 기존 전체 저장을 명시적으로 눌러야 서버에 쓴다. 가져오기와 닫기에는 서버 쓰기가 없고 원본 쿼터는 불변이다.
- 선택/적용 중 대상과 계정·팀·경기·쿼터 문맥을 재검사하고 지연·중복 응답을 차단한다. 다른 기기의 동시 쓰기를 원자적으로 잠그는 기능은 추가하지 않는다.

가장 강한 반론은 선택 절차가 수동 편성보다 번거로울 수 있고, 교체 OUT/IN이 함께 남은 기록이 오해를 만들 수 있다는 점이다. 표시 문구만으로 위험을 해결하지 않고 선택·유효성·저장 경계를 실제로 검사한다. 새 데이터 모델·권한·복잡한 추론이 필요하면 이 기능을 중단하며 현황판으로 자동 대체하지 않는다.

## 사용 방법

1. 같은 경기의 2쿼터 이후 빈 편집 화면에서 **이전 쿼터 기록에서 선수 가져오기**를 연다.
2. 가져올 선수를 직접 선택한다. 원본 IN/OUT과 위치, 선택 불가 사유를 확인한다. 아무도 자동 선택되지 않는다.
3. **N명 초안에 적용** 후 기존 피치에서 위치를 검토·수정한다. 이때 서버에는 저장되지 않는다.
4. **전체 저장**을 눌러 저장하거나 기존 뒤로가기의 미저장 확인에서 취소한다. 저장 확인에 실패하면 기존 재시도를 사용한다.
