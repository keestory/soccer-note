# Separate team player ranking tab

The user requested a separate tab for team player rankings. The deployed web/Capacitor navigation becomes Home / Matches / Ranking / Team. `/ranking` contains the existing six statistics and inclusive date range filters; `/team/players` focuses on roster management. `/ranking/[id]` shares the existing player statistics screen and returns to Ranking. The original player detail URL remains available.

The UI/UX agent reviewed information architecture, states, accessibility and native boundaries. Independent QA reviewed the patch and actual browser flows. One product writer made all changes. No auth/data-access rules, database schema, native SDK or separate Expo source changed. New ranking routes are noindex.

## Regression fixes

- Roster mutations now update the shared player list, so immediately switching to Ranking reflects edited names and deleted players. Root browser verification exercised a mock edit and delete followed by client-side navigation to Ranking, without a reload.
- Independent QA found that two-column date fields clipped the day at320px. The final stacked rows provide170px input width at320px; both the full date and calendar icon are visible in Korean and Spanish.
- Competition ties preserve1,1,3 and equal first-place styling. Null ratings display a dash. Players absent and records absent have separate states. The selected team is shown and ranking inputs are scoped to its ID.
