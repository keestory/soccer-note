## 최초 실패와 하네스 보정

[`최초 18건 실행`](initial-browser-results.json)은 15통과/3실패였다. 두 건은 동작 검증 전에 `page.reload(networkidle)`의 10초 한도에 걸렸다. 다른 경기 1건은 dashboard가 최신 경기만 표시하는데 두 번째 경기 링크를 바로 찾은 **QA 경로 오류**였다. 후자는 기존 `/matches` 전체 목록 링크를 거치도록 수정했다.

[`후속 진단`](followup/browser-results.json)에서는 앞선 두 동작이 수정 없는 제품에서 통과했지만 다른 사례의 준비 reload가 다시 10초를 초과했다. 당시 `document.readyState=loading`, heading과 메모 없음, 로컬 CSS/JS 요청과 합성 MOM 조회 대기가 관측됐다. 배경 요청만 남고 UI는 준비됐다고 해석하지 않는다. 정확한 지연 원인은 미확인이다.

이 근거로 문서 탐색만 30초로 제한하고 `networkidle` 대기와 UI assertion을 유지했다. 사용자 동작 assertion은 계속 10초다. 준비 실패 시 해당 context를 닫아 후속 검사에 남지 않도록 했다. 최종 전체 18건을 단독 브라우저로 다시 실행해 통과했다. 이는 클라우드 테스트 준비 시간 허용이며 운영 지연 시간·성능 통과의 증거가 아니다. 제품 코드를 테스트에 맞추어 변경하지 않았다.
